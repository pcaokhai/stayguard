# Data Model

Version 1.0 · 2026-09-30 · Owner: Tech lead

## 1. Ownership

| Database | Owner service | Migration tool | Location |
| --- | --- | --- | --- |
| `stayguard` (PostgreSQL, schema `app`) | API lane only | goose, forward-only SQL | `api/migrations/` |

No other service or tool writes to it. The web app never sees the database. Baseline DDL is produced by story SG-003, not pre-written here.

## 2. Tables

All tables carry `tenant_id` (except `tenants`, `payment_events` before matching) and have a row-level security policy (ADR-005). IDs are prefixed ULIDs stored as text.

### Tenancy and identity

| Table | Purpose | Key constraints |
| --- | --- | --- |
| `tenants` | One guesthouse business or one trial | `default_locale` in (vi, en); `currency` = VND; `is_trial`, `expires_at`; bank account number encrypted |
| `users` | Owner, receptionists, housekeeping | `role` in (OWNER, RECEPTIONIST, HOUSEKEEPING); unique (tenant_id, name) in the demo |
| `sessions` | Opaque session tokens | Primary key = SHA-256 of the token; `expires_at` indexed for cleanup |
| `building_permissions` | Access per user per building | Primary key (user_id, building_id); `level` in (NONE, VIEW, EDIT); `granted_by`, `granted_at` |

### Property structure

| Table | Purpose | Key constraints |
| --- | --- | --- |
| `properties` | A site owned by the tenant | `vertical` in (GUESTHOUSE) today; BOARDING_HOUSE added by the boarding-house pack |
| `buildings` | Buildings of a property | unique (tenant_id, code) |
| `floors` | Floors of a building | unique (building_id, level) |
| `unit_types` | Standard, VIP | `name` JSONB `{vi, en}`; `rate_plan` JSONB validated against `contracts/pricing/rate-plan.schema.json`; `rate_plan_version` |
| `units` | Rooms | `status` in (VACANT, OCCUPIED, TO_CLEAN, MAINTENANCE); unique (tenant_id, code); `attributes` JSONB for custom fields |

`OVERDUE` is not stored. It is derived when an overnight or daily stay is past its expected end.

### Stays and billing

| Table | Purpose | Key constraints |
| --- | --- | --- |
| `stays` | One guest stay | `rental_type` in (HOURLY, OVERNIGHT, DAILY); `status` in (ACTIVE, CHECKED_OUT); `deposit` ≥ 0; `check_in_at` set by the server; `rate_plan_snapshot` JSONB; `id_number_enc` optional; `billing_mode` default SESSION; unique (unit_id) where status = ACTIVE |
| `services` | Extras catalogue | `price` ≥ 0; `stock` ≥ 0; `name` JSONB |
| `stay_extras` | Extras on a stay | `quantity` > 0; `amount` = quantity × unit_amount (CHECK) |
| `invoices` | Frozen bill | one per stay; `bill_code` unique per tenant; `quote` JSONB is the frozen quote; `status` in (OPEN, PAID) |
| `payments` | Payment attempts | `method` in (CASH, TRANSFER); `status` in (PENDING, PAID, EXPIRED, MISMATCH); unique (invoice_id) where status = PENDING |
| `payment_events` | Inbound provider or simulator events | unique (provider, external_id); `result` in (SETTLED, MISMATCH, UNMATCHED, DUPLICATE_IGNORED) |

### Cash and shifts

| Table | Purpose | Key constraints |
| --- | --- | --- |
| `shifts` | A user's working shift | `status` in (OPEN, CLOSED); unique (user_id) where status = OPEN; `counted_cash`, `difference`, `reason` set on close |
| `cash_entries` | Every movement of drawer cash | `kind` in (DEPOSIT_IN, PAYMENT_IN, REFUND_OUT, PAYOUT_OUT); `amount` > 0; append-only |

Expected cash = opening float + DEPOSIT_IN + PAYMENT_IN − REFUND_OUT − PAYOUT_OUT for the shift.

### Operations

| Table | Purpose | Key constraints |
| --- | --- | --- |
| `housekeeping_tasks` | Rooms to clean | `status` in (OPEN, DONE); one OPEN per unit |
| `alerts` | Owner alerts | `kind` in (UNUSED_ROOM_REPORT, STAY_TIME_EDITED, CASH_SHORT, CASH_OVER); `details` JSONB |
| `audit_logs` | Who did what | Append-only: trigger rejects UPDATE and DELETE; `before`, `after` JSONB; `trace_id` |
| `idempotency_keys` | Stored responses | Primary key (tenant_id, route, key); `request_hash`; `expires_at` |

## 3. Modeling rules

| Topic | Rule |
| --- | --- |
| Money | `BIGINT` whole VND; CHECK constraints for signs; never `NUMERIC` with decimals, never float |
| Statuses | `TEXT` with a CHECK constraint, not database enums (cheaper to change) |
| Time | `timestamptz` in UTC; billing windows computed in the tenant time zone in Go |
| IDs | Text ULIDs with a type prefix (`room_`, `stay_`); generated by an ID port, sortable |
| Tenant links | Foreign keys are composite `(tenant_id, id)` so a row can never point at another tenant's row |
| Sensitive data | ID number and bank account number encrypted with AES-GCM using a key from the environment; masked on read; never in logs or audit `before`/`after` |
| Audit | Every sensitive command writes an audit row in the same transaction |
| Naming | snake_case, plural table names, `_at` for instants, `_id` for foreign keys |
| Rate plans | JSONB validated in Go against the JSON Schema; version bumps on every change; stays keep their snapshot |

## 4. Deltas from the design-phase plan

| Earlier design | Change | Reason | Story |
| --- | --- | --- | --- |
| `occupancies` with `mode` (session or contract) | `stays` with `billing_mode`; boarding house adds its own tables | Avoid a half-used generic table; the `BillingPolicy` port carries the seam | SG-003 |
| `pricing_snapshot` | Renamed `rate_plan_snapshot` on `stays` | Clearer; holds the whole rate plan | SG-203 |
| `invoices` plus lines | `invoices.quote` JSONB frozen at check-out | Immutable snapshot; only aggregates are queried | SG-205 |
| `charges` | `stay_extras` for extras; stay charges live in the quote | Extras need stock and quantity rules | SG-205 |
| (none) | `sessions`, `idempotency_keys` | Auth and retries | SG-102, SG-003 |
| (none) | `users.locale` (vi or en, default vi) | Per-user UI language; the tenant default_locale seeds it | SG-102 |
| (none) | `building_permissions` | Building-level access | SG-501 |
| (none) | `shifts`, `cash_entries` | Cash reconciliation | SG-503 |
| `audit_logs` optional | Written from the first sensitive command | Owner trust story | SG-003 |

## 5. Migration rules

Forward-only; no down migrations in shared environments. Expand, migrate, contract for any breaking change across releases. Migration numbers are reserved in the story plan to avoid clashes between lanes. Migrations change schema and reference data only; sample tenants come from the fixture loader, not from migrations. Every table added in a migration gets its RLS policy in the same migration; a test fails when a table in `app` has none.

## 6. Key queries and their indexes

| Query | Index |
| --- | --- |
| Room map: units of a building with active or unpaid stay | `units (tenant_id, building_id, code)`; `stays (unit_id) WHERE status = 'ACTIVE'`; `invoices (stay_id) WHERE status = 'OPEN'` |
| Match a payment event to a payment | `payments (tenant_id, reference_code) WHERE status = 'PENDING'` |
| Deduplicate a payment event | unique `payment_events (provider, external_id)` |
| Owner overview for a local day | `payments (tenant_id, paid_at)`; `cash_entries (tenant_id, created_at)`; `alerts (tenant_id, created_at DESC)` |
| Open housekeeping tasks | `housekeeping_tasks (tenant_id, status, unit_id) WHERE status = 'OPEN'` |
| Current shift of a user | unique `shifts (user_id) WHERE status = 'OPEN'` |
| Shift review and history | `shifts (tenant_id, user_id, closed_at DESC)`; `cash_entries (shift_id)` |
| Session lookup and cleanup | primary key on token hash; `sessions (expires_at)` |
| Trial cleanup | `tenants (expires_at) WHERE is_trial` |

Hot queries get an EXPLAIN in the PR that adds them.
