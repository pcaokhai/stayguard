## Understanding
docs/06 SG-201 asks for the room map read side: buildings the caller may see with level and status counters (AC1), rooms with status, bilingual unit type name and an active-stay summary with elapsed minutes and running total (AC2), OVERDUE derived and never stored (AC3), 403 `BUILDING_FORBIDDEN` for NONE and 404 for another tenant's ids (AC4), and 200 rooms at p95 <= 150 ms (AC5). docs/04 §2.3 gives the role and building matrix, already encoded in `domain/access` but not yet called by any handler: this is the first story to wire the `Authorizer`. docs/05 §2 says OVERDUE is derived when an overnight or daily stay is past its expected end; docs/02 §7.7 fixes windows in the tenant time zone and a grace period. SG-102 Rulings 4 and 8 hand over two things: derived building access (owner EDIT, others NONE) behind a port until SG-501, and a `ScopeFilter` AC for `listBuildings`. SG-101 (pricing) is not merged (docs/progress.md), so the running total is behind a port with a fake (tech lead decision, Ruling 1).

## Interfaces (in words)
- `BuildingLevels.Levels(ctx, caller, building ids)` returns the effective level per id (missing id means NONE). Used by listBuildings (filter) and by the building checks.
- `RoomRepo`: `Buildings(tx)` ids, codes and names of the caller's tenant; `Rooms(tx, filter)` where the filter is all, one building or one room, returning one row per unit joined with unit type name, floor level and the active stay (if any), ordered by building then code; `Timezone(tx)`. Every query filters `tenant_id` explicitly and RLS applies on top. Constant number of statements per request (no per-room queries).
- `StayQuoter.RunningTotal(ctx, snapshot, rental type, check-in, now, zone)` returns whole VND as `int64` (SG-101 introduces the `Vnd` type and replaces the port's implementation).
- Authorization order: role (`Authorizer`, `ScopeFilter` for listBuildings), then existence in the tenant (404), then level (403). Another tenant's id is indistinguishable from a missing one.
- Flag: `FF_S1_ROOM_MAP` off gates the three operations only: handler returns 404 `FEATURE_DISABLED` before any I/O (same pattern as `DEMO_DISABLED`). Read once at startup.
- All times come from the injected clock (rule 3). Money is `int64` VND (rule 1).

## Rulings (decisions needing the tech lead)
1. Running total: SG-101 is not merged, so a `StayQuoter` port with a fake proves AC2; the real adapter fails with `ErrPricingUnavailable` (503 `PRICING_UNAVAILABLE`) until SG-101 binds the engine. Keep `FF_S1_ROOM_MAP` off until that is done. Owner of the binding: SG-101 (or the first story after it). Decided by the tech lead.
2. Expected end for OVERDUE (open in docs): the first occurrence of the snapshot's `windowEnd` (overnight and daily) strictly after check-in, in the tenant zone; OVERDUE when now is after that plus `graceMinutes` (matches the late-fee grace of §7.7). A daily stay has no booked length in the data model, so after the first noon it stays OVERDUE until check-out; confirm.
3. Flag off returns 404 `FEATURE_DISABLED` for the three operations (docs/07 §8: flags disable endpoints); no contract change since codes are free text.
4. Building level stays derived (owner EDIT, others NONE) behind `BuildingLevels` until SG-501; VIEW is proven with a fake. `getMe` in SG-102 keeps its own copy of the derivation; SG-501 removes both.
5. No new dependency or tool.
6. Size: about 950 lines with tests. Tech lead chose two PRs. PR A (`feat/SG-201-rooms-read-api`): domain/room, app use cases and ports with fakes (AC1, AC3, AC4 logic). PR B (`feat/SG-201b-rooms-read-adapters`, from main after A): migration, postgres repo, derived permissions, pricing stub, handlers, problem mappings, flag config, wiring, benchmark (AC2, AC4 isolation, AC5, flag).
7. Contract fields without a column: `guestName` (stays has none) and `unitType.code` (unit_types has none) get migration 0005. `note` needs no column: it is the string `note` inside `units.attributes` when present, else null. SG-203 stores the guest name into `stays.guest_name`.
