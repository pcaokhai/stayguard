## Interfaces in words
- `UnitOfWork.Do(ctx, tenantID, fn)`: opens a transaction, sets the tenant as a transaction-local setting, runs `fn` with a tenant-scoped handle, commits on nil, rolls back on error or panic. Empty tenant is an error before any query. A use case without Do cannot reach a repository (repositories take the handle, not the pool).
- RLS policies read the transaction-local tenant setting; unset or empty compares false so zero rows return. The app role connects with `NOBYPASSRLS` and owns nothing; tables are owned by the migration role and forced under RLS.
- `IdempotencyStore.Begin(ctx, tenant, route, key, requestHash)`: returns Proceed, Replay(status, body) or error `ErrIdempotencyKeyReused`; `Complete(...)` stores the response in the same transaction as the effect. Hash is SHA-256 of the canonical body. TTL from config, default 24 h (Ruling 4).
- `AuditWriter.Append(ctx, entry)`: insert only, same transaction as the command; no personal data in `before` and `after`.
- `ReadinessProbe.Check(ctx)`: ping with a short timeout plus goose "no pending migrations"; `/readyz` maps failure to 503 problem+json and never leaks the cause.
- Tenant-isolation test (`TenantIsolation_SG003_TS08`, includes the NULL-tenant case of Ruling 7): create tenant A and tenant B through the maintenance role, each with a user, property, building, unit and an idempotency key. In a unit of work for A, list and fetch every table by B's ids: expect zero rows, and an update or delete of B's row affects zero rows; an insert naming B's tenant is rejected by the policy. Then a query run through the app pool with no tenant set returns zero rows from every table. Finally drop the explicit `tenant_id` filter in a deliberately naive query and show A still cannot see B (RLS as the second guard, ADR-005). Composite foreign keys: inserting a unit in A pointing at B's building fails. NULL-tenant case: the app role inserts an unmatched `payment_events` row (NULL `tenant_id`); with A set, with B set and with no tenant set, a select, update and delete see and touch zero rows of it; the maintenance role sees it (proves it exists); A cannot insert an event naming B, nor update a row to B's tenant; A's matched events are invisible to B.

## Risks and rollback
- RLS misconfiguration fails closed (empty results) and can look like a bug elsewhere; catalog-driven tests cover every table.
- A pooled connection keeping a tenant setting is a leak; transaction-local setting and the leak test guard it.
- Testcontainers needs Docker; the daemon is reachable on this machine now and CI runners have it. Container startup adds seconds; one container per package.
- goose is forward-only in shared environments; a wrong migration is fixed by a new one. Before merge the branch may rewrite 0001 to 0003 freely, nothing is deployed.
- Rollback: one squash-merged PR; revert it. Makefile stubs return with the revert.
