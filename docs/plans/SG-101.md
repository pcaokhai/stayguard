# Plan SG-101 Pricing engine
Status: PR A in review (money, rate plan); PR B not started
Lane API, slice none, depends SG-001 (merged). No contract change (Quote and BillLine schemas exist in `contracts/openapi.yaml`); no migration, no endpoint. Delivered as two PRs (Ruling 3): PR A money type and rate plan, PR B the engine, bill assembly and property tests.

## Understanding
docs/06 SG-101 asks for a pure pricing function that reproduces every case of `contracts/pricing/golden-cases.json` (25 cases, 2 error cases, 2 bill cases, AC1, AC5), rate plans validated against `rate-plan.schema.json` with field-level errors (AC2), property tests with a logged seed (AC3), no I/O imports and instants as arguments (AC4) and snapshot stability across plan versions (AC6). ADR-006 fixes whole-VND `int64`, a pure function of (rate plan, rental type, check-in, check-out) and the Python generator as the executable spec; docs/02 §7.7 gives the rules; api/CLAUDE.md puts money in a checked `Vnd` type and pricing in `domain/pricing`. The golden file carries flat plans (four prices per plan name) while the schema is richer (version, grace, windows); the Go test maps each flat plan to a full plan with the generator's constants (grace 15, overnight 21:00 to 12:00, daily 14:00 to 12:00, zone Asia/Ho_Chi_Minh). SG-201 left a `StayQuoter` port that returns `ErrPricingUnavailable`; binding the engine to it is a follow-up PR (Ruling 5), not part of this story.

## Acceptance criteria to test names
- AC1 → `PriceGolden_SG101_AC1` (table over every case of the file read at test time: total, capped flag, every line code, quantity, unit amount and amount), `PriceGoldenErrors_SG101_AC1` (both error cases return `ErrInvalidInterval`) and `GoldenFileShape_SG101_AC1` (counts 25, 2, 2 and the flat plans, so a regenerated file with a new shape fails loudly).
- AC2 → `RatePlanSchema_SG101_AC2` (valid plan accepted; table of invalid plans: missing field, wrong type, negative money, non-integer money, grace above 60, bad clock string "24:00" and "9:00", unknown extra property, wrong currency, version 0; each returns field-level errors with a JSON path and a stable reason code) and `RatePlanMatchesSchemaFile_SG101_AC2` (test-only: every table row is also validated with the real schema file via a JSON Schema library, and Go and the schema must agree on accept or reject, so the Go validator cannot drift from the contract).
- AC3 → `PriceProperties_SG101_AC3` (fixed seed constant, printed on failure; random plans and intervals: total never decreases as check-out moves later; HOURLY and OVERNIGHT never exceed the daily price and set `capped` exactly when clipped; sum of line amounts equals the total; every amount equals quantity times unit amount; no overflow error for money within range) and `VndChecked_SG101_AC3` (add, multiply and sum overflow return an error, never wrap).
- AC4 → `PricingPurity_SG101_AC4` (parses the package's non-test files: no import of os, io, net, database, log, math/rand, no call of `time.Now`, `time.Since` or `time.Until`; the existing layer boundary test stays green) and `PriceDeterministic_SG101_AC4` (same inputs, same output, any zone offset given as argument).
- AC5 → `BillGolden_SG101_AC5` (both `billCases` incl. the refund case) and `BillArithmetic_SG101_AC5` (balance due and refund due are never both positive; deposit equal to total gives zero both; extras multiply; overflow errors).
- AC6 → `SnapshotStable_SG101_AC6` (a stay stores the JSON of plan v1; the tenant plan then changes to v2; pricing the stored snapshot gives the v1 amount, a new stay with v2 gives the v2 amount; the snapshot round-trips byte-stable through parse and encode).

## Interfaces (in words)
- The engine receives instants and a zone, never a clock or a database. Rental type is a small enum local to the package; adapters convert from the stay's string. Rates and windows come from the plan, not constants: overnight window and daily window (start for early check-in fee, end for the billing-day boundary) are plan fields, grace is a plan field.
- Rules are exactly docs/02 §7.7 and the generator: grace blocks (full hours plus one when the remainder exceeds grace), hourly first-hour plus extra blocks capped at the daily price, overnight early and late blocks capped at the daily price, daily days ending at the window end with early fee before the window start and late fee capped at one daily price (a full-day late fee counts as another day). Minutes are whole minutes, seconds truncated. Check-out at or before check-in is `ErrInvalidInterval`.
- Quote lines use the generator's codes: FIRST_HOUR, EXTRA_HOUR, OVERNIGHT, EARLY_CHECKIN_HOUR, LATE_CHECKOUT_HOUR, DAILY, EARLY_CHECKIN_FEE, LATE_CHECKOUT_FEE. Validation errors are data for the HTTP layer later (422 with field paths); this story maps nothing to HTTP.
- Rule changes start in `generate_vectors.py` (CLAUDE.md §6 rule 2); this story does not edit `contracts/`.
